# Sail

## Find the agreement

Find it in the session context: a path the user passed, a written spec the
project or user points to, or the live conversation. If none is there, or it
has no way to verify, stop and ask.

If it came from a written spec, read `references/written-spec.md`. If several
fit, name them and ask. If you found it yourself, say which one you are taking
before starting; that is a report, not a request for approval.

## Execute

Work through the agreed conditions. Use each condition's verification method to
decide what to run or inspect.

- An unmet condition stays unmet. Do not call it met to look busy, or reword it
  to make it pass.
- If the agreement is silent on a local detail, use judgment. Silence is not
  permission to change the agreed outcome.

## Stop

Stop when a premise of the agreement no longer holds. Report which premise
failed and wait for the user's decision.

If the agreement must change, it goes back through the gate: reopen the
interview with `keel` instead of editing the spec and carrying on in one step.

## Report

Report what changed, what passed with evidence, and what is unmet when the work
is done. Evidence is the observed value that decides a condition, not a
restatement of it: a count for a count, a state for a state. If the agreement
already says it, add nothing.
