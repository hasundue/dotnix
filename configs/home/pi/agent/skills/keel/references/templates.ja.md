# テンプレート（日本語）

タスクごとにワークツリーのルートへ `SPEC.md` を 1 つ置く．見出しが構造であり，その下の文章はそうではない．短く保つ．読み返されない spec はゲートにならない．

日本語のセッションではドラフトを `SPEC.ja.md` として書く．承認時に `SPEC.en.md` へ翻訳し，独立したチェックを経て `SPEC.md` へ昇格させる．英語のセッションでは `SPEC.md` がドラフトであり，昇格はメタデータの更新だけ．ドラフトと翻訳候補はコミットしない．`SPEC.context.md` がある場合は `SPEC.md` と一緒にコミットし，マージ前に両方削除する．

フロントマターのキーは英語のままにする．`created` は作成日，`status` は `draft` / `agreed` / `done` / `blocked` のいずれか，`session_lang` は会話の言語コード，`translated` は英語になった日で，英語で書いた場合は空のまま．値のない項目は空にしておき，この説明を spec に写さない．`branch` やマージ後の項目は持たない．

## テンプレート

```markdown
---
created: <YYYY-MM-DD>
status: draft
session_lang: ja
translated:
---

# <短いタイトル>

## 現在の動作

<実行者が最初に読むパスと，その現在の動作．パスが変わったら更新する．>
<長くなった場合のみ，パスをワークツリーの `SPEC.context.md` に移し，このセクションの末尾からリンクする．`SPEC.context.md` は `SPEC.md` と一緒にコミットし，マージ前に削除する．>

## 設計

<実装を縛る決定を 1 行ずつ，理由とともに書く．自明でない判断に背景が必要なら `~/vault/research/<project>/<subject>.md` の research note へリンクする．背景そのものは写さない．決定やログのセクションは作らない．>

## 対象外

- <明示的に作らないもの>

## 受け入れ条件

<条件は素の `-` で書き，その検証方法をタブで字下げした `- [ ]` としてぶら下げる．コマンド，または期待する観察結果を添えた手作業の手順を書く．ユーザーの判断で終わる条件は何を決めるかだけを述べ，返答の形式は指定しない．>

- <観測できる結果>
  - [ ] <コマンド，または期待する観察結果を添えた手順>

## 停止条件

<タスク固有の制限と条件だけを書く．ない場合はこのセクションを省略する．全タスクに共通する停止条件は sail スキルに置く．>

## ブロッカー

<停止したときだけ追加する．試したこと，起きたこと，考えられる原因，選べる選択肢．>
```

## 言語とファイル名

見出しの英語対応と翻訳の手順は `task-note-lifecycle.md` に置く．日本語のドラフトを書くのに英語テンプレートを読む必要はない．承認後は本文も英語になり，ブロッカーや範囲の変更も英語で書く．

## 条件とチェックの規則

- `- [ ]` は未検証の条件そのものではなく，その条件を確かめる方法．
- `- [x] <方法> -- <コマンドと結果>` とし，何が証拠かを必ず添える．
- 検証できなかったものはチェックを外したままにし，`unmet: <理由>` を添える．
- `## 対象外` は素の `-` を使う．`[ ]` は検証方法だけに意味を持たせる．
- チェックを入れることは条件の再交渉ではない．条件の文言を変えるには新しい承認が必要．
- 検証方法にラベルは付けない．条件の数と検証の数を分けて数えられるようにする．

## 簡略例

```markdown
---
created: 2025-11-30
status: draft
session_lang: ja
translated:
---

# アイドルでセッションを切る

## 現在の動作

`src/auth/session.ts` はログイン時に `expiresAt = issuedAt + 24h` を設定し，以降更新しない．`tests/auth/session.test.ts` は現在 24 時間を前提にしている．

## 設計

- 認証済みリクエストごとに `expiresAt` を進め，絶対上限は変えない -- 上限はコンプライアンス要件のため．
- アイドル期限と絶対期限をテストで分ける．

## 対象外

- 永続ログイン，リフレッシュトークン，ロール別の期限
- 既存セッションの移行（旧ルールのまま期限切れになる）

## 受け入れ条件

- 最後のリクエストから 31 分後のリクエストが 401 で拒否される
  - [ ] `pnpm test tests/auth/session.test.ts -t idle`
- 最後のリクエストから 29 分後のリクエストが成功し，時計が進む
  - [ ] 同じテストファイルで `-t active`
- 24 時間の絶対上限が残る
  - [ ] 同じテストファイルで `-t absolute`

## 停止条件

- `src/billing/` に触れる必要が生きたら停止する
```
